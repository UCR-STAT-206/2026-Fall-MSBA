Cleaning Messy Data

Goals

  1. Identify common problems in real data such as missing values, suspicious values, inconsistent text, and numbers stored as text.
  2. Decide between dropping and imputing missing values.
  3. Use the .str methods for light text cleaning.
  4. Convert columns to the correct data type.

Why clean data?

Real data are rarely ready to analyze. They come from forms, spreadsheets, and business systems where people type things in different ways, leave cells blank, or copy values with symbols attached.

pandas gives us tools to find and fix many of these problems. Cleaning takes judgment, though: the code is the easy part, and deciding what the right fix is requires knowing the business context.

import pandas as pd

Setup: a small messy sales dataset

Handling missing data

There are two main strategies:

  • Drop the rows (or columns) with missing data.
  • Impute missing values by filling in a reasonable substitute value.

Neither approach is always right. Whether you choose to drop or impute, you must understand the missingness pattern.

Models for missigness

  • Missing Completely at Random (MCAR): The missingness pattern has no relationship with any observed or unobserved data.
    • Example: A digital weighing scale runs out of batteries. Every person weighed in this hypothetical study had the same chance of encountering the dead scale.
    • \(\Pr(\text{Missing} \mid \text{Observed}, \text{Unobserved}) = \Pr(\text{Missing})\)
  • Missing at Random (MAR): The probability of missingness depends only on known, observed data.
    • Example: You know that older participants were sampled towards the end of the study which coincided with the period when the battery was dying. Age is observed, and within each age group, missingess is random.
    • \(\Pr(\text{Missing} \mid \text{Observed}, \text{Unobserved}) = \Pr(\text{Missing} \mid \text{Observed})\)
  • Missing Not at Random (MNAR): Data are MNAR if they are neither MCAR nor MAR. This is the most complex case.
    • Example: The scale has a mechanical flaw in which weights above a certain threshold cause it to shut down. Heavy weights are systematically unobserved.
    • \(\Pr(\text{Missing} \mid \text{Observed}, \text{Unobserved})\) cannot be simplified and depends at least on the missing data.

Complete-Case Analysis: Dropping missing rows

For a quick report, we might only use rows where units_sold is known:

clean_drop = sales.dropna(subset=["units_sold"])
clean_drop
month region units_sold price_per_unit sales_rep
0 2025-01 North 100.0 10.0 Alice
2 2025-03 North 130.0 NaN Alice
3 2025-04 East 120.0 9.5 Chris
5 2025-06 East 150.0 9.5 Chris
  • Choosing to focus on the observed data is making the assumption that your observed data are a representative random subsample.
  • subset= limits the check to the listed columns. Without it, dropna() removes any row with a missing value in any column.
  • Dropping is reasonable when few rows are affected and we have plenty of data left.
  • Dropping is risky when the missing rows differ systematically from the rest (for example, a region that always reports late).

Imputing with a summary value

For price_per_unit, suppose we believe prices are fairly stable, so the average is a reasonable stand-in:

price_mean = sales["price_per_unit"].mean()    # NaN values are skipped automatically
price_mean
np.float64(9.7)
sales_imputed = sales.copy()     # copy so the original stays untouched
sales_imputed["price_per_unit"] = sales_imputed["price_per_unit"].fillna(price_mean)
sales_imputed
month region units_sold price_per_unit sales_rep
0 2025-01 North 100.0 10.0 Alice
1 2025-02 South NaN 10.0 Bob
2 2025-03 North 130.0 9.7 Alice
3 2025-04 East 120.0 9.5 Chris
4 2025-05 South NaN 9.5 NaN
5 2025-06 East 150.0 9.5 Chris
  • We are making a potentially strong assumption. A proper statistical model for the missingness pattern is ideal but not always available.
    • State these kinds of assumptions clearly and upfront.
    • If you make a leap of faith like this, you must justify foregoing a more careful analytic analysis.
    • Domain knowledge can be helpful here.
  • .fillna(value) replaces missing values with value.
  • .copy() matters. Without it, changes to sales_imputed could also change sales.
NoteOther ways to fill

fillna(0) fills with a constant. fillna("Unknown") works for text columns. Sometimes “missing” really means zero (no sales that month) and sometimes it means “unknown.” Check with whoever produced the data.

pandas cannot catch every error

pandas can tell you what is missing, but not what is wrong yet present. Here is a slightly altered table:

sales2 = sales_imputed.copy()
sales2.loc[3, "units_sold"] = 5_000     # set row labeled 3, column units_sold
sales2
month region units_sold price_per_unit sales_rep
0 2025-01 North 100.0 10.0 Alice
1 2025-02 South NaN 10.0 Bob
2 2025-03 North 130.0 9.7 Alice
3 2025-04 East 5000.0 9.5 Chris
4 2025-05 South NaN 9.5 NaN
5 2025-06 East 150.0 9.5 Chris

To pandas, 5_000 is just another number. Descriptive statistics help us notice problems:

If typical months are 100 to 150 units, 5,000 is suspicious (an extra zero? the wrong row?). A person with domain knowledge must decide what is impossible or unlikely.

Suppose we know no region sells more than 500 units a month. We can filter to find suspicious rows:

sales2[sales2["units_sold"] > 500]

3 2025-04 East 5000.0 9.5 Chris

Once found, the fix is a business decision: correct the value, set it to missing, or drop the row.

Cleaning text columns

Text entered by people is often inconsistent. Consider a list of regions typed by different people:

region = pd.Series([" north", "South ", "NORTH", "East", "south", "EAST "])
region.value_counts()
 north    1
South     1
NORTH     1
East      1
south     1
EAST      1
Name: count, dtype: int64

.value_counts() counts each distinct value. pandas treats "north", "NORTH", and " north" as three different categories, which would break any summary by region.

The .str methods

A Series of text has a .str accessor that applies string operations to every element:

region.str.strip()        # remove leading/trailing spaces
0    north
1    South
2    NORTH
3     East
4    south
5     EAST
dtype: str
region.str.lower()        # all lower case
0     north
1    south 
2     north
3      east
4     south
5     east 
dtype: str
region.str.title()        # Capitalize Each Word
0     North
1    South 
2     North
3      East
4     South
5     East 
dtype: str

Chain them to clean everything in one go:

region_clean = region.str.strip().str.title()
region_clean.value_counts()
North    2
South    2
East     2
Name: count, dtype: int64

Now there are just three categories (East, North, South), which is what we wanted.

Clean and convert

The steps are:

  1. Treat "N/A" as missing.
  2. Remove $ and commas.
  3. Convert to numbers.
rev_clean = rev.copy()

# 1. Replace "N/A" with a proper missing value
rev_clean["revenue"] = rev_clean["revenue"].replace("N/A", pd.NA)
rev_clean
month revenue
0 2025-01 $10,000
1 2025-02 $11,500
2 2025-03 NaN
3 2025-04 $9,750 
# 2. Remove currency symbols and commas
rev_clean["revenue"] = rev_clean["revenue"].str.replace("$", "", regex=False)
rev_clean["revenue"] = rev_clean["revenue"].str.replace(",", "", regex=False)
rev_clean
month revenue
0 2025-01 10000
1 2025-02 11500
2 2025-03 NaN
3 2025-04 9750 
# 3. Convert to numbers
rev_clean["revenue"] = pd.to_numeric(rev_clean["revenue"])
rev_clean.dtypes
month          str
revenue    float64
dtype: object

Now we can compute with it:

rev_clean["revenue"].mean()      # missing value is skipped
np.float64(10416.666666666666)
TipA shortcut

pd.to_numeric(..., errors="coerce") turns anything it cannot convert (like "N/A") into a missing value, so step 1 can often be skipped:

pd.to_numeric(rev["revenue"].str.replace("$", "", regex=False)
                            .str.replace(",", "", regex=False),
              errors="coerce")

Be careful though: this also silently hides unexpected bad values. Look at what was converted to missing before moving on.

pandas did not know how to handle $ and N/A by itself because those are conventions of the business system that produced the data.

Summary

Problem Tool
Find missing values df.isna().sum(), df.info()
Drop rows with missing df.dropna(subset=[...])
Fill missing values df["col"].fillna(value)
Spot unusual values df["col"].describe(), filtering
Inconsistent text .str.strip(), .str.lower(), .value_counts()
Text that should be numbers .str.replace(...), pd.to_numeric(...)
Text that should be dates pd.to_datetime(...)

A good habit: work on a copy of your data, and write down every assumption you make while cleaning.
