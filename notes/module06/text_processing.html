Working with Text

Goals

  1. Distinguish plain, rich, and structured text, and know why how text is stored can matter for an analysis.
  2. Use Python’s built-in string tools to split, clean, and count text.
  3. Write simple regular expressions to find and extract patterns.
  4. Apply the same ideas to a column of text in a DataFrame.

Packages

import os
import re
from collections import Counter
from html import unescape

import pandas as pd

Three kinds of text documents

  • Rich text: content and style are stored together (think Microsoft Word). A file contains information about bold or italic as well as the words.
  • Plain text: only the symbols themselves. A .txt file, a .csv file, a cell in a notebook, or Python source code.
  • Structured text: plain text that uses a markup language to describe content. For example, HTML:
snippet = '<p>Price: <b>$19.99</b> &mdash; in stock</p>'
print(snippet)
<p>Price: <b>$19.99</b> &mdash; in stock</p>

A web browser renders this as “Price: $19.99 — in stock”. Your data may arrive with the markup still attached, and you must remove it before analyzing the content. One way to do this is with a regular expression:

# remove anything between < and >
no_tags = re.sub(r"<[^>]+>", "", snippet)

# convert &mdash; into the real character
unescape(no_tags)
'Price: $19.99 — in stock'

Encodings

A computer stores numbers, not letters. A character encoding is a table that says which number stands for which symbol.

  • ASCII: a small table, mostly English letters, digits, and punctuation.
  • Unicode: a table for (almost) every symbol in every writing system, including accents and emoji. UTF-8 is the most common way to store Unicode, and is the standard for the web.
print(ord("A"), chr(65))    # character <-> number
print(len("café"), len("café".encode("utf-8"))) # 4 characters, but 5 bytes
65 A
4 5

You rarely work with encodings directly, but you should recognize the symptoms of a bad encoding:

raw_bytes = "café".encode("utf-8")
raw_bytes.decode("latin-1") # decoding with the *wrong* table
'cafÃ©'

Strange symbols such as Ã© where an accented letter should be almost always mean that the file was read with the wrong encoding. Most readers let you specify one: open(path, encoding="utf-8") or pd.read_csv(path, encoding="latin-1"). If one choice gives an error or nonsense, try a different encoding.

Characters you cannot see

UTF-8 text may contain several kinds of “blank” characters. A non-breaking space looks like a space but is a different character:

text = "Test Analyst"           #   is a non-breaking space
print(text)
print(text == "Test Analyst")   # looks identical, but is not
Test Analyst
False
text.replace(" ", "_")          # misses it: no ordinary space to replace
'Test\xa0Analyst'
text.split()                    # split() with no argument handles any whitespace
['Test', 'Analyst']
re.sub(r"\s+", " ", text)       # so does the regex \s, and this normalizes it
'Test Analyst'

If two strings look identical but compare as unequal, you should suspect invisible characters.

Formatting with f-strings

An f-string inserts values into a string. After a colon you can control the format.

revenue = 1249.5
share = 0.0732
print(f"Revenue: ${revenue:,.2f}")     # comma separators, 2 decimals
print(f"Share: {share:.1%}")           # as a percentage
Revenue: $1,249.50
Share: 7.3%

Words

A first attempt at splitting into words:

poem.split(" ")[:10]
['I',
 'have',
 'eaten\nthe',
 'plums\nthat',
 'were',
 'in\nthe',
 'icebox\n\nand',
 'which\nyou',
 'were',
 'probably\nsaving\nfor']

The newline characters are stuck to words: a word at the end of a line and the first word of the next stanza are glued together into one piece with \n\n in the middle. Splitting on any whitespace fixes this. We also convert to lower case, so that The and the are the same word:

words = poem.lower().split()
print(len(words), "words,", len(set(words)), "distinct")
28 words, 23 distinct

Real text has punctuation, which would remain attached to words; for example, "cold.". A regular expression can pull out just the pieces made of letters and apostrophes:

def tokenize(text):
    """Return the lower-case words in a string."""
    return re.findall(r"[a-z']+", text.lower())

tokenize("Don't panic! It's 5 o'clock...")
["don't", 'panic', "it's", "o'clock"]

Pairs of words

Counting single words ignores word order. A cheap way to keep a little order is to count bigrams: pairs of neighboring words.

pairs = [" ".join(pair) for pair in zip(words, words[1:])]
Counter(pairs).most_common(3)
[('i have', 1), ('have eaten', 1), ('eaten the', 1)]

zip(words, words[1:]) lines up each word with the one after it.

Regular expressions

A regular expression (regex) is a compact pattern that describes a set of strings. You can use it to find, extract, or replace text that has a certain shape, like a date, a dollar amount, or a product code.

Useful tools to help you learn:

  • Python’s re module and its regex HOWTO.
  • regex101.com: type a pattern and some text, and it highlights and explains the matches. Select the “Python” flavor.

Building blocks

Pattern Matches
abc the literal text abc
. any one character except a newline
\d one digit; \D is anything but a digit
\w one letter, digit, or underscore
\s one whitespace character (space, tab, newline)
[aeiou], [0-9], [A-Za-z] one character from a set or range
[^>] one character that is not in the set
* + ? the previous item 0 or more, 1 or more, 0 or 1 times
{4} {2,3} the previous item exactly 4 times, or 2 to 3 times
a\|b a or b
^ $ the start / the end of the string
( ) a group: lets you pull out part of a match
\. \$ \( a literal ., $, or ( (a backslash escapes a special character)

Write patterns as raw strings, r"...", so that Python does not interpret the backslashes before the regex engine sees them.

The re module

note = "Order #1042 shipped on 2025-03-14 to Riverside, CA 92521. Total: $1,249.50"

re.search() finds the first match anywhere in the string and returns a match object, or None:

m = re.search(r"\d{4}-\d{2}-\d{2}", note)
print(m)
print(m.group(), m.span())
<re.Match object; span=(23, 33), match='2025-03-14'>
2025-03-14 (23, 33)
re.findall(r"\d+", note)             # all runs of digits
['1042', '2025', '03', '14', '92521', '1', '249', '50']

Parentheses create groups that you can pull out separately:

m = re.search(r"(\d{4})-(\d{2})-(\d{2})", note)
m.groups()
('2025', '03', '14')
m = re.search(r"\$([\d,]+\.\d{2})", note)      # a dollar sign, then digits/commas, a point, 2 digits
amount = m.group(1)                             # group 1: just the part in the parentheses
float(amount.replace(",", ""))
1249.5

re.sub() replaces matches and re.split() splits on them:

re.sub(r"\d", "#", note)
'Order ##### shipped on ####-##-## to Riverside, CA #####. Total: $#,###.##'
re.split(r"[,;]\s*", "red, green;blue,  yellow")
['red', 'green', 'blue', 'yellow']

No match means None

If the pattern is not found, re.search() returns None, and None.group() is an error.

m = re.search(r"\d{4}-\d{2}-\d{2}", "no date here")
print(m)
m.group()
None
---------------------------------------------------------------------------
AttributeError                            Traceback (most recent call last)
Cell In[35], line 3
      1 m = re.search(r"\d{4}-\d{2}-\d{2}", "no date here")
      2 print(m)
----> 3 m.group()

AttributeError: 'NoneType' object has no attribute 'group'
m = re.search(r"\d{4}-\d{2}-\d{2}", "no date here")
m.group() if m else "no date found"

Always check or validate re.search() results.

Quantifiers are greedy

+ and * match as much as possible. Compare:

re.sub(r"<.+>", "", snippet)    # greedy: from the first < to the LAST >
''

The result is an empty string: the greedy pattern swallowed everything between the first < and the last >, including the price.

re.sub(r"<[^>]+>", "", snippet) # "one or more characters that are not >"
'Price: $19.99 &mdash; in stock'

tenure = comments.str.extract(r"(\d+)\s*\+?\s*years?", flags=re.IGNORECASE)[0]

matched = comments[tenure.notna()]

  • Look at the third comment above, which says “1.5 years”. What number did the pattern extract? Why? How would you change the pattern?
  • Does the pattern pick the right number when a comment contains several numbers, or a range like “10-20%”? Try r"(\d+(?:\.\d+)?)\s*%" to extract percentages and examine those matches.
  • The people with a tenure comment are those who chose to write one. Can we say anything about the typical employee from them?
  • Job titles are also typed by hand. What tools might help you group the titles into a handful of categories?
TipA workflow for handling messy text
  1. Look at a sample of the raw values.
  2. Write the simplest pattern that could work.
  3. Count the matches and read both matched and unmatched rows.
  4. Refine, and repeat.

Do not try to write the perfect pattern in one go.
