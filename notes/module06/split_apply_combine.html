Split-Apply-Combine

Goals

  1. Understand the split-apply-combine pattern for analyzing grouped data.
  2. Use groupby to summarize (agg), add group-aware columns (transform), and keep or drop whole groups (filter).
  3. Recognize that group structure is not always given to you: groups may have to be constructed from numbers or text, or may be hiding in the data entirely.
  4. Appreciate how ignoring group structure can lead to misleading summaries.

The split-apply-combine pattern

Many data analysis problems involve the application of a split-apply-combine strategy, where you break up a big problem into manageable pieces, operate on each piece independently and then put all the pieces back together.

– Hadley Wickham, The Split-Apply-Combine Strategy for Data Analysis (2011)

  • Split: divide the data into groups using one or more key variables.
  • Apply: compute something on each group independently (a summary, a transformation, a model).
  • Combine: collect the results into a new table or column.

The pattern appears at every stage of an analysis: preparing data (ranking or standardizing within groups), summarizing (counts and averages by segment), and modeling (a separate model for each region or customer type).

Why not just loop?

We already know enough to do this by hand: loop over the species, filter the rows, and compute.

for species in sorted(penguins["species"].unique()):
    subset = penguins[penguins["species"] == species]
    print(species, round(subset["body_mass_g"].mean(), 1))
Adelie 3700.7
Chinstrap 3733.1
Gentoo 5076.0

That works for one number and one grouping variable. But what if we also want the median and the count? What if we group by island too? What if we want the answers in a table we can sort or export? Every change means more bookkeeping code. groupby does the splitting, applying, and combining for us.

penguins.groupby("species")["body_mass_g"].mean().round(1)
species
Adelie       3700.7
Chinstrap    3733.1
Gentoo       5076.0
Name: body_mass_g, dtype: float64

Apply and combine

Aggregation

An aggregation reduces each group to a few numbers. The .agg() method with named aggregation lets us choose the output names: each keyword is new_name=("column", "function").

mass_summary = (
    penguins
    .groupby("species")
    .agg(
        n_penguins=("body_mass_g", "count"),
        avg_mass_g=("body_mass_g", "mean"),
        median_mass_g=("body_mass_g", "median"),
        sd_mass_g=("body_mass_g", "std"),
    )
    .round(1)
)
mass_summary
n_penguins avg_mass_g median_mass_g sd_mass_g
species
Adelie 151 3700.7 3700.0 458.6
Chinstrap 68 3733.1 3700.0 384.3
Gentoo 123 5076.0 5000.0 504.1

Common built-in functions are "count", "size", "sum", "mean", "median", "std", "min", and "max".

Notecount vs size

"count" counts the non-missing values in a column, while "size" counts rows. They differ when there are missing values:

(After reset_index() the labels are columns, so index=False no longer throws them away. If we had skipped reset_index(), index=False would have deleted the species and island names from the file.)

Example: sex differences

sex has missing values, so we choose to drop those rows for this question only.

sexed = penguins.dropna(subset=["sex"])

sex_mass = (
  sexed
  .groupby(["species", "sex"])["body_mass_g"]
  .mean()
  .unstack("sex")          # turn the sex level into columns
)
sex_mass["difference"] = sex_mass["male"] - sex_mass["female"]
sex_mass.round(1)

species
Adelie 3368.8 4043.5 674.7

.unstack("sex") moves one level of the index into the columns, which makes comparisons such as male minus female a simple subtraction.

Transformation

A transformation computes a value for every row, using information from that row’s group. The result has the same number of rows as the original, so it can be stored as a new column.

def zscore(x):
  """How many standard deviations each value is from the mean."""
  return (x - x.mean()) / x.std()

penguins["mass_z"] = penguins.groupby("species")["body_mass_g"].transform(zscore)
penguins[["species", "body_mass_g", "mass_z"]].sample(5, random_state=1)
species body_mass_g mass_z
103 Adelie 4250.0 1.197947
126 Adelie 3275.0 -0.928246
12 Adelie 3200.0 -1.091799
249 Gentoo 4875.0 -0.398750
239 Gentoo 5300.0 0.444310
  • transform hands our function each group’s column as a Series, and expects back a Series of the same length.
  • A mass_z of 2 means “two standard deviations heavier than the average of its own species”. This is a different statement from “heavy compared with all penguins”.

For common cases you can pass the name of a function:

penguins["rel_mass"] = (
  penguins["body_mass_g"]
  / penguins.groupby("species")["body_mass_g"].transform("mean")
)
penguins[["species", "body_mass_g", "rel_mass"]].sample(5, random_state=1)

103 Adelie 4250.0 1.148443
126 Adelie 3275.0 0.884977
12 Adelie 3200.0 0.864710
249 Gentoo 4875.0 0.960399
239 Gentoo 5300.0 1.044126

A rel_mass of 1.0 means “exactly average for its species”.

Filtering groups

.filter() keeps or drops whole groups based on a condition on the group. Here we keep only species-island combinations with at least 50 penguins:

well_sampled = (
    penguins
    .groupby(["species", "island"])
    .filter(lambda g: len(g) >= 50)
)

well_sampled.groupby(["species", "island"]).size()
species    island   
Adelie     Dream         56
           Torgersen     51
Chinstrap  Dream         68
Gentoo     Biscoe       123
dtype: int64

The lambda g: len(g) >= 50 is a one-line function. It receives each group’s sub-table g and returns True (keep) or False (drop). Groups with few observations produce unreliable averages, so a minimum size is a common safeguard.

Where do groups come from?

So far the groups came ready-made: species, island, and sex are columns in the table. This is the easy case. Real data are rarely so convenient, and the most important group structure is often not labeled. Groups can arise in four ways:

Source of the groups Example Tool
1. Already a column species groupby("species")
2. Built from a number “heavy” vs “light” penguins np.where, pd.cut, pd.qcut
3. Built from text support tickets sorted into topics .str.contains() + np.select
4. Hidden in the data a mixture of groups nobody recorded you must notice it
WarningGroup structure is not always given or obvious

Much of the value of an analyst is the ability to discover structure that the data do not announce.

Even labeled groups have traps

groupby silently ignores rows whose key is missing:

penguins.groupby("sex").size()
sex
female    165
male      168
dtype: int64
penguins.groupby("sex", dropna=False).size()
sex
female    165
male      168
NaN         9
dtype: int64

The first result accounts for fewer penguins than the table contains. Nine rows vanished from the answer without any warning. Always check that your group sizes add up to the number of rows you expect.

Groups built from numbers

To compare “big” and “small” penguins we must first define big:

penguins["is_big"] = penguins["body_mass_g"] >= 4500
penguins["is_big"].value_counts()
is_big
False    224
True     118
Name: count, dtype: int64

Averaging a True/False column gives the proportion of True values, so we can answer “what share of each species is big?”:

penguins.groupby("species")["is_big"].mean().round(3)
species
Adelie       0.053
Chinstrap    0.044
Gentoo       0.870
Name: is_big, dtype: float64

To split a number into several named tiers, use pd.cut (you choose the cut points) or pd.qcut (cut points chosen so each tier has about the same number of rows):

penguins["mass_tier"] = pd.qcut(
  penguins["body_mass_g"], q=3, labels=["light", "medium", "heavy"]
)
penguins["mass_tier"].value_counts()
mass_tier
light     117
heavy     113
medium    112
Name: count, dtype: int64
pd.crosstab(penguins["species"], penguins["mass_tier"])
mass_tier light medium heavy
species
Adelie 81 63 7
Chinstrap 36 31 1
Gentoo 0 18 105

pd.crosstab counts how many rows fall in each combination of two labels. The tiers are not spread evenly over species: the constructed groups are tangled up with the labeled ones.

Groups built from text

Suppose we have support tickets, and the only information about the topic is the free-text subject line.

tickets = pd.DataFrame({
  "subject": [
    "Refund for duplicate charge",
    "Cannot log in to my account",
    "Please refund my last order",
    "Password reset email never arrives",
    "App crashes when I open it",
    "Charged twice this month",
    "Login page shows an error",
    "App freezes on the checkout screen",
    "Where is my refund?",
    "Question about my invoice",
    "Cannot sign in after the update",
    "Crash on startup",
    "Thanks for the great service!",
  ],
  "hours_to_resolve": [30, 4, 26, 6, 52, 40, 5, 60, 28, 12, 3, 48, 2],
})

There is no topic column, so we create one by testing each subject for keywords (see the text notes). np.select takes a list of conditions and a list of labels, and picks the label of the first condition that is True:

subject = tickets["subject"].str.lower()

conditions = [
  subject.str.contains("refund|charge|invoice"),
  subject.str.contains("log in|login|sign in|password"),
  subject.str.contains("crash|freez"),
]
labels = ["billing", "access", "app"]

tickets["topic"] = np.select(conditions, labels, default="other")
tickets[["subject", "topic"]]
subject topic
0 Refund for duplicate charge billing
1 Cannot log in to my account access
2 Please refund my last order billing
3 Password reset email never arrives access
4 App crashes when I open it app
5 Charged twice this month billing
6 Login page shows an error access
7 App freezes on the checkout screen app
8 Where is my refund? billing
9 Question about my invoice billing

Now the usual split-apply-combine works on the group we created:

(
  tickets
  .groupby("topic")
  .agg(n_tickets=("subject", "count"), avg_hours=("hours_to_resolve", "mean"))
  .round(1)
  .sort_values("avg_hours", ascending=False)
)
n_tickets avg_hours
topic
app 3 53.3
billing 5 27.2
access 4 4.5
other 1 2.0

Two cautions. First, the answer depends on our rules: a different keyword list produces different groups. Second, always count how many rows landed in "other" and read some of them. If that group is large, the rules are missing something.

Groups hidden in the data

Now the hardest case. Imagine the species column had been lost before the data reached you. We would still have the measurements. Could we notice that there are groups?

Consider the flipper lengths of all penguins mixed together:

flipper_counts = pd.cut(penguins["flipper_length_mm"], bins=range(170, 240, 5)).value_counts()
flipper_counts.sort_index()
flipper_length_mm
(170, 175]     2
(175, 180]    11
(180, 185]    28
(185, 190]    58
(190, 195]    57
(195, 200]    38
(200, 205]    18
(205, 210]    30
(210, 215]    33
(215, 220]    32
(220, 225]    20
(225, 230]    14
(230, 235]     1
Name: count, dtype: int64

The counts rise, dip around 200-205 mm, and rise again. A single “typical” flipper length does not describe this population, because there are (at least) two kinds of penguins. If we split at the dip, do we recover real groups?

penguins["flipper_group"] = np.where(
  penguins["flipper_length_mm"] >= 206,
  "long",
  "short"
)
pd.crosstab(penguins["flipper_group"], penguins["species"])
species Adelie Chinstrap Gentoo
flipper_group
long 2 6 122
short 149 62 1

A rule based on a single measurement nearly separates Gentoo from the other two species: almost every “long” penguin is a Gentoo, and almost every Gentoo is “long”. The group structure was there all along, and it was visible in the data.

Bad summary statistics

Ignoring group structure

What if we ignore the groups? Compare the spread of body mass overall with the spread within species:

print("overall sd:", round(penguins["body_mass_g"].std(), 1))
penguins.groupby("species")["body_mass_g"].std().round(1)
overall sd: 802.0
species
Adelie       458.6
Chinstrap    384.3
Gentoo       504.1
Name: body_mass_g, dtype: float64

Much of the overall variation is just the difference between species.

Labels can also be proxies for something else. Compare average body mass by island, then by island and species:

penguins.groupby("island")["body_mass_g"].mean().round(0)
island
Biscoe       4716.0
Dream        3713.0
Torgersen    3706.0
Name: body_mass_g, dtype: float64
pd.crosstab(penguins["island"], penguins["species"])
species Adelie Chinstrap Gentoo
island
Biscoe 44 0 123
Dream 56 68 0
Torgersen 51 0 0 
penguins.groupby(["island", "species"])["body_mass_g"].mean().round(0)
island     species  
Biscoe     Adelie       3710.0
           Gentoo       5076.0
Dream      Adelie       3688.0
           Chinstrap    3733.0
Torgersen  Adelie       3706.0
Name: body_mass_g, dtype: float64

Biscoe penguins look much heavier than Dream or Torgersen penguins. But look at the cross-tabulation: every Gentoo penguin in the data lives on Biscoe, and Gentoo is a large species. Among Adelie penguins, the three islands have almost the same average. The apparent “island effect” is a species effect in disguise.

Simpson’s Paradox

For our last example we use .apply(), the most general “apply” step. It runs any function on each group’s table. Here, the function computes the correlation between bill length and bill depth:

def bill_correlation(g):
    return g["bill_length_mm"].corr(g["bill_depth_mm"])

overall = penguins["bill_length_mm"].corr(penguins["bill_depth_mm"])
print("all penguins together:", round(overall, 3))

penguins.groupby("species").apply(bill_correlation).round(3)
all penguins together: -0.235
species
Adelie       0.391
Chinstrap    0.654
Gentoo       0.643
dtype: float64

Taken together, longer bills go with shallower bills (negative correlation). Within each species, longer bills go with deeper bills (positive). The sign of the relationship flips depending on whether we look at the mixture or at its parts. This phenomenon is known as Simpson’s paradox. We will revisit this phenomenon in discussing visualization.

ImportantTakeaway

A summary computed over a mixture of groups may describe none of the groups. Before you trust an overall average or correlation, ask: could there be groups in here that I have not accounted for?

Summary

Goal Code
Summarize by group df.groupby("g").agg(name=("col", "mean"))

Keep only some groups df.groupby("g").filter(lambda g: len(g) >= 30)
