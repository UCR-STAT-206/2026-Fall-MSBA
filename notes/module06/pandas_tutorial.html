Pandas Tutorial: Selecting, Reading, and Combining Data

Goals

  1. Select rows and columns by label (.loc) and by position (.iloc).
  2. Control how files are read and written, and combine several files into one table.
  3. Combine tables with pd.concat() and .merge()
  4. Understand how pandas stores data types and missing values, and how types change without warning.
  5. Rename and drop columns, and write a multi-step cleaning pipeline that is readable.

Indexing and subsetting

Every DataFrame has row labels (the index) and column labels. There are two ways to point at a piece of the table:

By Tool Meaning
label .loc “the row named …, the column named …”
position .iloc “the 3rd row, the 2nd column” (counting from 0)

To see the difference, we need row labels that are not just the numbers 0, 1, 2, … Here are six penguins, one for every 60th row, with names for row labels:

Filtering with .loc

A boolean mask is a column of True/False values, one per row. Combine one with a list of columns to say “these rows, those columns”:

tmp.loc[tmp["body_mass_g"] > 4000, ["species", "body_mass_g", "sex"]]
species body_mass_g sex
Daniela Gentoo 4600.0 female
Elizabeth Gentoo 4875.0 female

This is the version to prefer: the rows and columns are chosen in one step.Square brackets (df[...]) also work for quick selections:

Syntax Returns
df["a"] one column, as a Series
df[["a", "b"]] several columns, as a DataFrame
df[5:10] rows 5 to 9 (a slice by position)
df[mask] rows where mask is True

Changing values

.loc can also be used on the left of an = to change values in place:

tmp.loc["Daniela", "body_mass_g"] = 5000.0                        # one cell
tmp.loc[tmp["species"] == "Gentoo", "island"] = "Biscoe (check)"  # all rows matching a condition

WarningChained assignment does nothing

Selecting first and assigning second is a common mistake:

tmp[tmp["species"] == "Gentoo"]["body_mass_g"] = 0
tmp[["species", "body_mass_g"]]
/tmp/ipykernel_4409/160912952.py:1: ChainedAssignmentError: A value is being set on a copy of a DataFrame or Series through chained assignment.
Such chained assignment never works to update the original DataFrame or Series, because the intermediate object on which we are setting values always behaves as a copy (due to Copy-on-Write).

Try using '.loc[row_indexer, col_indexer] = value' instead, to perform the assignment in a single step.

See the documentation for a more detailed explanation: https://pandas.pydata.org/docs/dev/user_guide/migration.html#chained-assignment
  tmp[tmp["species"] == "Gentoo"]["body_mass_g"] = 0
species body_mass_g
Albert Adelie 3750.0
Beatrix Adelie 3150.0
Carlos Adelie 3150.0
Daniela Gentoo 5000.0
Elizabeth Gentoo 4875.0
Fatima Chinstrap 3300.0

tmp[mask] produces a new temporary table, so the assignment lands on the temporary copy and is thrown away. pandas may warn you, but the values in tmp are unchanged. Always assign in a single .loc[rows, column] = value step.

Specifying structure

pandas guesses the type of each column. The guess is likely to be wrong whenever a file uses its own conventions. Here is a small file that uses -999 and the word missing for unknown values, and has a date column:

raw = """id,date,amount,region
001,2025-03-01,19.99,West
002,2025-03-02,-999,East
003,2025-03-05,24.50,missing
004,2025-03-09,7.25,West"""

naive = pd.read_csv(StringIO(raw))
naive
id date amount region
0 1 2025-03-01 19.99 West
1 2 2025-03-02 -999.00 East
2 3 2025-03-05 24.50 missing
3 4 2025-03-09 7.25 West 
naive.dtypes
id          int64
date          str
amount    float64
region        str
dtype: object

Three things went wrong:

  1. id lost its leading zeros,
  2. date is just text, and
  3. -999 is being treated as a real amount (it would drag an average down).

We fix each with a reader option:

better = pd.read_csv(
    StringIO(raw),
    na_values=["-999", "missing"],   # extra strings that mean "missing"
    parse_dates=["date"],            # convert to real dates
    dtype={"id": str},               # keep as text, preserving "001"
)
better
id date amount region
0 001 2025-03-01 19.99 West
1 002 2025-03-02 NaN East
2 003 2025-03-05 24.50 NaN
3 004 2025-03-09 7.25 West 
better.dtypes
id                   str
date      datetime64[us]
amount           float64
region               str
dtype: object
Tip

pandas already treats empty cells and the text NA as missing. You only need na_values for additional codes like -999. Familiarize yourself with missing value conventions of different systems.

Writing files

Methods named .to_*() export a table. .to_csv() is the most common.

os.makedirs("output", exist_ok=True)     # create a folder for our results

for species, group in penguins.groupby("species"):
    filepath = os.path.join("output", f"penguins_{species}.csv")
    group.to_csv(filepath, index=False)
    print("saved", filepath, group.shape)
saved output/penguins_Adelie.csv (152, 8)
saved output/penguins_Chinstrap.csv (68, 8)
saved output/penguins_Gentoo.csv (124, 8)

index=False avoids writing the row labels as an extra column. When the row labels are just 0, 1, 2, …, that is what you want.

WarningWhen the index holds information

If the index carries real information, such as a summary table whose rows are labeled by species, then index=False throws it away and you cannot tell which row is which. Use .reset_index() first to turn the labels into an ordinary column.

Common reasons to export:

  • saving a cleaned copy for later, sharing a summary table, and
  • saving intermediate results in a long pipeline so you do not have to rerun everything.

Combining many files

Data often arrive in pieces: one file per month, per region, or per species. glob finds the files matching a pattern; pd.concat() stacks the tables.

files = sorted(glob.glob(os.path.join("output", "penguins_*.csv")))
files
['output/penguins_Adelie.csv',
 'output/penguins_Chinstrap.csv',
 'output/penguins_Gentoo.csv']
combined = pd.concat(
  [pd.read_csv(f).assign(source_file = os.path.basename(f)) for f in files],
  ignore_index = True,
)
print(combined.shape)
combined["source_file"].value_counts()
(344, 9)
source_file
penguins_Adelie.csv       152
penguins_Gentoo.csv       124
penguins_Chinstrap.csv     68
Name: count, dtype: int64
  • sorted() makes the file order the same on every computer.
  • .assign(source_file=...) records which file each row came from. This costs nothing now and is very helpful when you later find a strange value.
  • ignore_index=True renumbers the rows 0, 1, 2, … instead of repeating each file’s own numbering.

Combining tables

Tool What it does Use when
pd.concat() Stacks tables on top of each other the tables have the same columns (e.g. one file per month)
.merge() Matches rows using a shared column (a key), adding columns one table describes things in another (e.g. a lookup table)

Merging

Suppose a colleague gives us a small table of extra information about each island. (This table is made up, purely for illustration.)

island_info = pd.DataFrame({
    "island": ["Biscoe", "Dream"],
    "survey_team": ["Team A", "Team B"],
})
island_info
island survey_team
0 Biscoe Team A
1 Dream Team B

Notice that Torgersen is missing from the lookup table. Let us merge it onto the penguins:

left = penguins.merge(island_info,
  on = "island",
  how = "left"
)
left.loc[left["island"] == "Torgersen", ["species", "island", "survey_team"]].head(3)
species island survey_team
0 Adelie Torgersen NaN
1 Adelie Torgersen NaN
2 Adelie Torgersen NaN

Notice this table has shape (344, 9).

inner = penguins.merge(island_info,
  on = "island",
  how = "inner"
)
inner.loc[inner["island"] == "Torgersen", ["species", "island", "survey_team"]].head(3)
species island survey_team

Notice this table has shape (292, 9).

  • how = "left" keeps every row of the left table (penguins) and fills in NaN where the lookup has no match.
  • how = "inner" keeps only rows that match in both tables, so the Torgersen penguins quietly disappeared.

Neither is wrong, but you must know which one you chose. A good habit after every merge is to compare the number of rows before and after, and count the unmatched rows.

  • In the left merge example, there were 344 rows before the merge and 344 rows after the merge.
  • There are 52 penguins missing island information.

Duplicate keys

What if the lookup table has the same key twice?

island_info_dup = pd.concat([island_info, island_info.iloc[[0]]], ignore_index=True)

  on = "island",
  how = "left"

print(len(penguins), "->", len(dup))

Data types

penguins.dtypes
species                  str
island                   str
bill_length_mm       float64
bill_depth_mm        float64

body_mass_g          float64

  • float64: numbers with decimals (and missing values, stored as NaN).
  • int64: whole numbers. These cannot hold a missing value.
  • str: text. A missing text value is also NaN.

Silent casting

An integer column that gains a missing value silently converts data to float:

years = penguins["year"].head(5).copy()
print(years.dtype)

years[0] = None
print(years.dtype)
years
int64

1    2007.0
2    2007.0
3    2007.0

If you need whole numbers and missing values, ask for the nullable integer type, written with a capital I:

years.astype("Int64")
0    <NA>
1    2007
2    2007
3    2007
4    2007
Name: year, dtype: Int64

Here the missing value is shown as <NA>.

Converting types

.astype() converts a column. Here are two conversion you are likely to use in practice:

# whole numbers with possible missing values
penguins["year"].astype("Int64").dtype
Int64Dtype()
# a column with a fixed set of labels can be stored as a category
penguins["species"].astype("category").dtype
CategoricalDtype(categories=['Adelie', 'Chinstrap', 'Gentoo'], ordered=False, categories_dtype=str)

A category can also have a meaningful order. Plain text sorts alphabetically, which is rarely the order you want for ordinal data (such as ratings or sizes):

sizes = pd.Series(
  ["medium", "small", "large", "small", "large", "medium"]
)
print(sizes.sort_values().tolist()) # alphabetical

size_type = pd.CategoricalDtype(
  ["small", "medium", "large"],
  ordered=True
)
sizes_cat = sizes.astype(size_type)
print(sizes_cat.sort_values().tolist()) # in the order we specified
['large', 'large', 'medium', 'medium', 'small', 'small']
['small', 'small', 'medium', 'medium', 'large', 'large']

Statistics and missing values

Most summary methods skip missing values by default, which is convenient but easy to forget.

cols = penguins[["bill_length_mm", "body_mass_g"]]
cols.mean() # skipna = True: missing values ignored
bill_length_mm      43.921930
body_mass_g       4201.754386
dtype: float64
cols.mean(skipna = False) # any missing value makes the answer NaN
bill_length_mm   NaN
body_mass_g      NaN
dtype: float64

Double-check the sample size used in calculating summary statistics:

cols.count()  # how many values each mean is based on
bill_length_mm    342
body_mass_g       342
dtype: int64

The axis option says which direction to compute in.

  • The default axis=0 collapses the rows (one answer per column).
  • axis=1 collapses the columns (one answer per row).
penguins[["bill_length_mm", "bill_depth_mm"]].mean(axis=1).head()
0    28.90
1    28.45
2    29.15
3      NaN
4    28.00
dtype: float64
Warning

Remember that averaging across columns like this only makes sense if the data have the same units.

Renaming and dropping

Most methods return a new table and leave the original alone. Save the result to a variable to keep it.

renamed = penguins.rename(

NoteWhy we avoid inplace = True

Many methods accept inplace = True, which modifies the table you called it on. It is easy to run twice by accident, it cannot be chained, and the pandas developers recommend against it. Prefer reassignment; for example df = df.method(...). This style makes it easy to spot where a table changes in your code.

Adding rows

Rows are best added by building them first and stacking them once with concat:

new_rows = pd.DataFrame([

    "island": "Torgersen",

    "bill_depth_mm": 20.0,
    "flipper_length_mm": 180.0,
    "body_mass_g": 3500.0,

Method chaining

A pipeline applies several operations in a row, each acting on the result of the previous one. Wrap the whole expression in parentheses so you can put one step on each line:

(
  penguins
  .dropna(subset = ["body_mass_g"])
  .assign(mass_kg = lambda d: d["body_mass_g"] / 1000)
  .query("mass_kg > 5")
  .sort_values("mass_kg", ascending = False)
  .loc[:, ["species", "island", "sex", "mass_kg"]]
  .head()
)

  • .assign(name = ...) creates a new column.
  • The lambda d: ... syntax defines an anonymous function. Here d stands for “the table as it is at this point in the pipeline”.
  • Each line does one thing, so the code reads like a recipe, and you can comment out a line to see what it did.
  • If a chain becomes long or confusing, break it into smaller steps with names for the intermediate tables.
