Working with Probability Distributions

Goals

  1. Generate random numbers reproducibly using a seeded random number generator.
  2. Draw samples from common probability distributions, such as uniform, normal, binomial, and Poisson.
  3. Randomly sample from, and shuffle, existing data.
  4. Use simulation to answer simple business questions and to see ideas like the law of large numbers in action.

Why generate random numbers?

Randomness is a tool for modeling uncertainty. It can be harnessed to:

  • simulate demand, arrivals, defaults, or returns when we cannot calculate an answer by hand,
  • draw a random sample or split data into training and test sets,
  • explore “what-if” scenarios,
  • check intuition about a statistical idea by trying it many times.
import numpy as np

Random number generators

Computers do not produce truly random numbers. They produce pseudorandom numbers: sequences that look random but are generated by a deterministic algorithm. While potentially insecure for encryption purposes, it does mean we can reproduce results.

The recommended way to work with randomness in NumPy is to create a generator object with np.random.default_rng():

rng = np.random.default_rng(seed=206)

The seed determines the starting point of the determnistic sequence. Two generators created with the same seed produce exactly the same numbers.

rng1 = np.random.default_rng(seed=206)
rng2 = np.random.default_rng(seed=206)
rng1.random(3), rng2.random(3)
(array([0.86200941, 0.38843713, 0.9970794 ]),
 array([0.86200941, 0.38843713, 0.9970794 ]))

If you omit the seed, NumPy will use your computer’s state to choose one.

TipSet a seed for anything you share

Always set a seed when you want your results to be reproducible: in homework, reports, or anything a colleague might re-run. It is good practice to create the generator once near the top of your script and reuse it.

NoteWhat about np.random.rand()?

You may see older code that uses functions like np.random.rand(), np.random.randn(), or np.random.seed(). These still work, but the generator-based approach shown here is the modern recommendation.

Uniform random numbers

The most basic method is .random(), which draws numbers uniformly between 0 and 1.

rng = np.random.default_rng(seed=1)
rng.random()        # a single number
0.5118216247002567
rng.random(5)       # an array of 5 numbers
array([0.9504637 , 0.14415961, 0.94864945, 0.31183145, 0.42332645])
rng.random((2, 3))  # a 2 by 3 array
array([[0.82770259, 0.40919914, 0.54959369],
       [0.02755911, 0.75351311, 0.53814331]])

To draw uniformly between other bounds \(a\) and \(b\), use .uniform():

rng.uniform(low=50, high=100, size=5)
array([66.48658582, 89.42143517, 65.15974146, 72.67489447, 56.70208486])

For random whole numbers, use .integers(). Note that the upper bound is excluded by default, just like range().

rng.integers(low=1, high=7, size=10)   # ten rolls of a six-sided die
array([3, 3, 6, 2, 4, 2, 1, 5, 1, 2])

Common probability distributions

NumPy generators have a method for most “nice” distributions you will encounter. The size argument controls how many values are simulated, and may be given as an integer or a tuple defining an array shape.

Normal distribution

The normal (bell curve) distribution is described by its mean loc and standard deviation scale.

rng = np.random.default_rng(seed=2)
heights = rng.normal(loc=170, scale=10, size=1000)
heights[:5]
array([171.89053382, 164.77251559, 165.86936457, 145.58532617,
       187.99707383])

We can check that the sample behaves like the distribution we asked for:

heights.mean(), heights.std()
(np.float64(169.77590939357168), np.float64(10.128274848400915))

These are close to 170 and 10, but not exactly equal, because the sample is random. We use the vectorized tools from the previous notes to answer questions about it:

(heights > 185).mean()  # fraction of people taller than 185
np.float64(0.065)

Binomial distribution

The binomial distribution counts the number of successes in n independent trials, each with success probability p. For example, if each of 20 customers independently buys with probability 0.3, how many purchases do we see in a day?

rng.binomial(n=20, p=0.3, size=10)  # ten simulated days
array([8, 4, 6, 6, 7, 4, 7, 8, 5, 6])

A single coin flip is the special case n=1:

rng.binomial(n=1, p=0.5, size=10)
array([0, 1, 1, 1, 0, 1, 1, 0, 1, 0])

Poisson distribution

The Poisson distribution models the count of events in a fixed interval when events occur independently at an average rate lam. Typical uses are customers arriving per hour, or support tickets per day.

rng.poisson(lam=4, size=10)  # arrivals per hour, average of 4
array([3, 1, 7, 4, 3, 2, 2, 4, 3, 6])

Exponential distribution

The exponential distribution models the waiting time between Poisson events. Its scale parameter is the average wait.

rng.exponential(scale=15, size=5)  # minutes between arrivals
array([ 4.1280955 , 10.56733829, 57.86240424,  1.16394801, 37.3125094 ])

Summary

Method Typical use Key parameters
.random() uniform on [0, 1) size
.uniform() uniform on [a, b) low, high
.integers() random whole numbers low, high
.normal() measurements, errors, returns loc, scale
.binomial() number of successes n, p
.poisson() counts of events lam
.exponential() waiting times scale

See the NumPy documentation for the full list of distributions.

NoteDensity and probability calculations

The NumPy generator only draws samples. If you need exact probabilities, such as \(P(X \le 3)\) for a binomial, or the value of a density function, use the scipy.stats module. We will not need this for now, since we can approximate many probabilities by simulation, as shown below.

Sampling and shuffling

Random choice

.choice() selects random elements from an existing array.

rng = np.random.default_rng(seed=3)
customers = np.array(["Ana", "Ben", "Chloe", "Dev", "Elena", "Farid"])

rng.choice(customers, size=3)  # with replacement by default!
array(['Elena', 'Ana', 'Ben'], dtype='<U5')

Notice that the default is to sample with replacement, so the same element can appear twice. For a sample without replacement, set replace=False:

rng.choice(customers, size=3, replace=False)
array(['Ana', 'Elena', 'Farid'], dtype='<U5')

You can also assign unequal probabilities with the p argument:

rng.choice(["small", "medium", "large"], size=10, p=[0.5, 0.3, 0.2])
array(['small', 'small', 'small', 'small', 'medium', 'small', 'small',
       'medium', 'small', 'medium'], dtype='<U6')

Shuffling

.permutation() returns a randomly reordered copy of an array. This is handy for random splits: for example, to pick random rows for a test set.

rng.permutation(10)
array([5, 2, 3, 1, 6, 4, 8, 7, 0, 9])
order = rng.permutation(len(customers))
customers[order]
array(['Chloe', 'Ana', 'Dev', 'Farid', 'Elena', 'Ben'], dtype='<U5')

There is also .shuffle(), which reorders an array in place, modifying the original. Recall our earlier discussion of views and copies: prefer .permutation() unless you specifically want to change the original.

Simulation

The real power of random number generation is simulation: answer a question by imitating a process many times and looking at the results. Vectorization makes this fast.

Example: the law of large numbers

If you flip a fair coin more and more times, the fraction of heads settles near 0.5.

rng = np.random.default_rng(seed=4)

flips = rng.binomial(n=1, p=0.5, size=100_000)

for n in [10, 100, 1_000, 10_000, 100_000]:
    print(n, flips[:n].mean())
10 0.7
100 0.53
1000 0.529
10000 0.501
100000 0.49986

With few flips, the average can be far from 0.5. With many, it gets close. This is the law of large numbers.

Example: daily demand and out-of-stock events

A shop stocks 50 units each morning. Daily demand is, on average, 45 units with a standard deviation of 8 units. Assuming a normal model can be used to describe demand, how often does the shop run out of stock?

rng = np.random.default_rng(seed=5)

demand = rng.normal(loc=45, scale=8, size=100_000)
(demand > 50).mean()
np.float64(0.26633)

We estimate an out-of-stock probability around 27%. This is an empirical probability. This idea is ubiquitous throughout statistics. The law of large numbers and central limit theorem relate empirical estimates to theoretical probabilistic models, and are the engines that make simulation a useful tool.

  • Law of large numbers: Under appropriate conditions, empirical estimates tend towards their underlying theoretical probabilities.
  • Central limit theorem: Under appropriate conditions, the distribution of empirical estimates tends towards a certain normal distribution.

Example: expected revenue under uncertainty

Suppose we get a Poisson number of orders per day (average 20), and each order is worth about $35 on average with a standard deviation of $10. What is the distribution of daily revenue? A simple approach is to simulate the number of orders for each day, then add up that many random order values.

rng = np.random.default_rng(seed=6)
n_days = 10_000

n_orders = rng.poisson(lam=20, size=n_days)
daily_revenue = np.array([
    rng.normal(loc=35, scale=10, size=k).sum() for k in n_orders
])

daily_revenue.mean(), daily_revenue.std()
(np.float64(697.4855509511007), np.float64(161.42593062648388))
np.percentile(daily_revenue, [5, 50, 95])
array([443.59735837, 691.26502918, 972.42823332])

The last line gives a plausible range of daily revenue: there is a 90% chance revenue falls between the 5th and 95th percentile.

Exercises

  1. Create a generator with seed 123. Draw 10 random integers between 1 and 100 (inclusive of 100). Repeat with a new generator using the same seed and verify you get the same numbers.

  2. Simulate 10,000 rolls of two six-sided dice and compute the sum for each roll.

    1. What is the average sum?
    2. Estimate the probability that the sum is 7.
    3. How does your estimate compare to the exact answer of \(6/36\)?

  3. A call center receives an average of 12 calls per hour. This is often modeled with a Poisson distribution.

    1. Simulate 10,000 hours of call counts.
    2. In what fraction of hours are there more than 18 calls?
    3. The center can handle at most 15 calls per hour. How often is it overwhelmed?

  4. A marketing email has a 4% click rate. If you send it to 500 people, simulate the number of clicks 10,000 times.

    1. What is an appropriate distributional model for this scenario?
    2. What is the average number of clicks?
    3. What is the probability of getting at least 30 clicks?

  5. (Challenge) Simulate the law of large numbers for a fair six-sided die. Plot, or print, the running average of the rolls as the number of rolls increases. What value does it approach? (Hint: np.cumsum and np.arange may help.)
